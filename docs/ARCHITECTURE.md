# 系统架构与强制隔离规则

## 服务组成

- Nginx：公网HTTPS入口。
- FastAPI：管理后台API与业务规则。
- PostgreSQL 16：账号、关键词、内容、任务和发布结果。
- Redis 7：任务队列、账号运行锁和短期状态。
- Browser Worker：后续加入，执行百度/谷歌采集和知乎页面操作。

## 账号隔离边界

1. 所有账号业务表必须包含不可为空的 `account_id` 外键。
2. 所有查询必须先限定 `account_id`，禁止先全表读取后在应用层过滤。
3. 每个账号使用独立持久化浏览器 Profile，不允许复用 Cookie 或 localStorage。
4. 每个账号拥有独立任务队列与互斥锁；同一账号最多一个浏览器任务运行。
5. 关键词、文章、回答、商品、链接、提示词和统计默认不可跨账号引用。
6. “复制配置”创建真实副本，不建立会随源账号变化的共享引用。
7. 单账号导出、恢复、停用或删除不得修改其他账号数据。

## 关键词扩展顺序

每个平台独立执行：

1. 搜索主词并采集页面底部关联词。
2. 将当前层候选词按去除空白后的字符长度升序排列；长度相同保持页面出现顺序。
3. 依次搜索当前层的最短、第二短、第三短关键词并采集子关联词。
4. 当前层全部扩展后仍未达到目标数量，才进入下一层。
5. 搜索过的关键词记录到账号级 visited 集合，禁止重复搜索。
6. 达到目标数量立即停止；候选耗尽、验证码或连续失败时暂停并记录原因。

百度读取“相关搜索”，谷歌读取“用户还搜索了”。DOM定位必须以语义和文本为主，不能依赖固定屏幕坐标。

## 资源约束

目标服务器为4核、3.8GiB内存、29GB磁盘。初始只允许一个 Browser Worker 并发，PostgreSQL、Redis和后端设置内存上限；运行数据必须配置日志轮转和截图保留期限。
